1. Project Overview

BNI Enterprises BDMS is an enterprise-grade inventory and financial management solution engineered from the ground up by Yasin Ullah. Designed specifically for high-volume motorcycle dealerships, it eliminates manual ledgers by digitizing the entire business lifecycle.

It handles procurement, inventory tracking at the chassis/motor level, dynamic sales margins, tax calculations, installment scheduling, and full double-entry accounting via integrated ledgers and cheque registers.

2. Technical Architecture & System Requirements

  • Backend Engine: PHP (7.4 or 8.x compatibility) for robust server-side processing.
  • Database Layer: MySQL 5.7+ or MariaDB structured for high-speed relational queries.
  • Frontend Stack: HTML5, CSS3, JavaScript (ES6), jQuery, Select2, DataTables, SweetAlert2.
  • Security - Encryption: `PASSWORD_DEFAULT` (Bcrypt) hashing algorithm.
  • Security - CSRF: Cryptographically secure unique tokens per session.
  • Security - Brute Force: Intelligent IP banning after 7 failed attempts within a 3-hour window.
  • Security - Session Hardening: Configurable idle timeouts (default 40 mins) and absolute expirations.
  • Security - Verification: Custom-generated SVG mathematical captcha for login gates.

4. Role-Based Access Control (RBAC)

A rigorous RBAC engine guards the application against unauthorized internal manipulation.

  • Administrator (Level 0): Unrestricted access to all modules, global settings, and destructive table actions.
  • Manager (Level 1): Confined to daily operations (Dashboard, Inventory viewing) without access to role deletion or system calibration.
  • Matrix Granularity: Permissions are strictly evaluated at the matrix intersection of Page and Action (can_view, can_add, can_edit, can_delete).

5.1 Intelligent Dashboard

The central command node providing real-time telemetry on business health and asset liquidity.

  • Model-wise Analytics: Live breakdown of stock states (e.g., E8S M2: 2 Inventory, 1 Sold, 1 Available).
  • Revenue Feed: Recent Sales grid displaying Date, Chassis, Model, Price, and Exact Extracted Margin.
  • Procurement Feed: Recent Stock additions showing Date, Chassis, Price, and current Status.

5.2 Inventory / Stock Control

Surgical tracking of every physical asset inside the dealership network.

  • Multi-Dimensional Filters: Text Search, 4-State Status (In Stock, Sold, Returned, Reserved), Model Taxonomy, Colorway, Chronological Range.
  • Grid Architecture: Sr#, Chassis, Motor#, Model, Color, Purchase Price, Status, Selling Price, Selling Date, Margin.
  • Mass Operations: Bulk Deletion routines and full dataset CSV Extraction for external audits.

5.3 Purchase Entry & Procurement

The ingestion workflow for new stock, immediately binding physical assets to financial ledgers.

  • Header Metadata: Order Date, Inventory Date, Supplier, Cheque Routing Info (Number/Bank/Date/Amount), PO Notes.
  • Asset Specification: Chassis Number (with strict uniqueness validation), Motor Number, Model, Color, Purchase Price, Safeguard Notes.
  • Seamless Interruption: Integrated modals permit the creation of new Suppliers or Models mid-workflow without state loss.

5.4 Sales Entry, Invoicing & Quotations

The revenue generation engine, featuring automated profit protection and client fulfillment.

  • Transaction Data: Select Asset, Selling Date, Price, Purchase Price (Visible for Profit Guard), Auto-calculated Tax, Auto-calculated Net Margin.
  • CRM Integration: Select existing profiles or instantly create new entities (Name, Phone, CNIC, Address).
  • Capital Flow: Payment Method, Down Payment, Total Installment Splitting, Installment Amount, First Due Date.
  • Accessory Linkage: Bind physical accessories to the sale, dynamically adjusting the final cart price.
  • Pre-Sales (Quotations): Generate quotes that reserve inventory and convert to live sales with a single click.

5.5 Installment & Financing System

Advanced chronologic management of distributed payment plans.

  • Algorithmic Generation: If a transaction features a partial down payment, the engine automatically splits the remainder into monthly schedule rows.
  • Lifecycle Tracking: Monitors Amount Paid versus Installment Amount. Automatically calculates and enforces Penalty Fees for delinquent accounts.

5.6 Returns Management

Protocol for handling aborted sales and recovering physical assets into the inventory pool.

  • Execution Fields: Target Sold Bike, Return Date, Refund Amount, Refund Routing (Cash/Cheque), Operational Notes.
  • Systemic Reversal: Reverts the asset status from sold back to returned, inverses the double-entry ledger records, and registers the outgoing refund capital.

5.7 Financial Ecosystem: Cheques & Ledgers

Absolute financial transparency enforced through immutable double-entry accounting.

  • Cheque Register: Tracks all inbound and outbound bank instruments. Fields include Bank, Date, Amount, Type, Status (Pending, Cleared, Bounced), Party, and Reference ID.
  • Ledger Engine: Every sale inherently debits the customer ledger; every payment credits it. Identical mirrored logic applies to suppliers. Delivers instantaneous running balances.

5.8 Customers & Suppliers (CRM)

Centralized directory for all external business relationships and historical interactions.

  • Customer Matrix: Name, Phone, CNIC, Address, Aggregated Bikes Purchased, Aggregated Capital Spent.
  • Supplier Matrix: Name, Contact, Address, Total Procurement Orders, Total Capital Transferred.

5.9 System Settings & Calibration

Global environmental variables and core maintenance routines.

  • Core Configs: Company Name, Branch Name, Currency Symbol, Tax Rate (%), Tax Vector (Applied to Purchase vs Selling Price), Invoice Visibility Toggles, Session Hardening parameters.
  • System Operations: 1-Click Database SQL Extraction (Backup) and Injection (Restore). UI Theme toggling. Security credential updates.

6. Business Logic, Math & Tax Formulas

The BDMS core relies on strict mathematical constants to guarantee absolute financial accuracy.

1. Base Profit Extractor

Margin = Selling_Price - Purchase_Price - Auto_Tax_Amount

2. Dynamic Taxation Vectors

IF (Setting == 'Tax_On_Purchase'):
    Tax_Amount = Purchase_Price * (Tax_Rate / 100)

IF (Setting == 'Tax_On_Selling'):
    Tax_Amount = Selling_Price * (Tax_Rate / 100)

3. Aggregated Cart Value

Total_Sale_Value = Selling_Price + Sum(Accessories_Final_Price)

4. Chronologic Installment Splitting

Remaining_Capital = Total_Sale_Value - Down_Payment
Monthly_Node = Remaining_Capital / Total_Installment_Count

5. Ledger Double-Entry Protocol (Sale Scenario)

  • System generates a DEBIT node for the Customer equaling the Total_Sale_Value.
  • If Down_Payment > 0, system generates a CREDIT node for the Customer equaling the Down_Payment.
  • The running balance is structurally validated and updated in real-time.
