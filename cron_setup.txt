 Applies to : gobuykar_bni (live domain)

 WHAT THIS CRON DOES
 -------------------
 Runs cron.php once per day. cron.php:
   - Exports a full backup (schema + data) of the live database.
   - Compresses it into the "thedbbackups" folder (auto-created).
   - Keeps ONLY the newest 20 backups (deletes the oldest each run).
   - Optionally emails the backup to you (optional).

============================================================
 STEP 1 - UPLOAD cron.php
============================================================
Upload cron.php to the SAME folder where index.php lives.

Likely paths (confirm in cPanel File Manager):
  A) /home/gobuykar/public_html/cron.php
       (if the app runs at the domain root)

  B) /home/gobuykar/public_html/inventory/cron.php
       (if the app runs in an "inventory" subfolder)

Use the REAL path (from File Manager) in the command below.

============================================================
 STEP 2 - VERIFY DATABASE CREDENTIALS IN cron.php
============================================================
Open cron.php and confirm these lines match your live database:

    $DB_HOST = 'localhost:3306';      // or just 'localhost'
    $DB_USER = 'gobuykar_yasin';
    $DB_PASS = 'yasin@1234';
    $DB_NAME = 'gobuykar_bni';

If any value is wrong, the cron job will fail silently.

============================================================
 STEP 3 - ADD THE CRON JOB IN cPanel
============================================================
Go to: cPanel -> Cron Jobs -> Add New Cron Job

FILL IN THESE VALUES:

    Common Settings : Once Per Day
    Minute          : 30
    Hour            : 3
    Day             : *
    Month           : *
    Weekday         : *

COMMAND (recommended - Option A, PHP CLI, no key needed):

    /usr/local/bin/php /home/gobuykar/public_html/inventory/cron.php >/dev/null 2>&1

    - Replace the path with your real upload path from Step 1.
    - ">/dev/null 2>&1" stops cPanel from emailing you the
      "Backup OK" output every single day.

IF "/usr/local/bin/php" DOES NOT WORK:
   Find your PHP version in cPanel -> MultiPHP Manager, then use the
   domain-specific binary, for example:

    /usr/local/bin/ea-php82 /home/gobuykar/public_html/inventory/cron.php >/dev/null 2>&1

   (replace ea-php82 with your actual version, e.g. ea-php74, ea-php81, ea-php83)

============================================================
 OPTION B - RUN VIA URL (only if PHP CLI is unavailable)
============================================================
1. In cron.php, change the secret key to a long random string:
       $SECRET_KEY = 'some_long_random_secret_string_here';

2. Use this command:
       wget -q -O /dev/null "https://gobuykar.com/cron.php?key=yasin134"

============================================================
 STEP 4 - SAVE AND TEST
============================================================
1. Click "Add New Cron Job".
2. Run once manually (via SSH) or wait for the scheduled time (3:30 AM).
3. Confirm a .sql.gz file appears in the "thedbbackups" folder.

============================================================
 OPTIONAL - EMAIL THE BACKUP TO YOURSELF
============================================================
In cron.php set:

    $EMAIL_BACKUP = true;
    $EMAIL_TO     = 'you@example.com';
    $EMAIL_FROM   = 'backup@yourdomain.com';  // must be a real mailbox on your domain

NOTE: The emailed attachment is ~33% larger than the .sql.gz file on disk
      (base64 encoding). For large databases, rely on the server copy or use
      off-site FTP instead of email.

============================================================
 IMPORTANT SECURITY NOTES
============================================================
- The "thedbbackups" folder is auto-sealed with .htaccess (no web access).
- Change $SECRET_KEY if you use Option B (URL method).
- Periodically download a copy of backups to your own computer (off-site copy).
- A server-only backup is not a complete backup strategy.
